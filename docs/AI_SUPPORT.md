# AI 고객 문의 기능

## 사용 순서

1. 상품 상세의 **이 상품 문의하기**, 주문 내역의 **주문 문의**, 마이페이지의 **내 문의**에서 접수한다.
2. 관리자는 마이페이지의 **문의 관리**에서 문의를 연다.
3. AI 연결 시 비동기로 초안을 생성한다. 관리자 상세 화면에서 상태를 자동 확인하고 새 초안을 검토 후 적용한다.
4. **AI 생성 이력과 참고 자료**에서 생성 당시 자료와 실제 인용한 근거 ID를 확인한다.
5. 답변을 수정한 후 **답변 승인하고 공개**를 누른다. 이 시점부터 고객이 볼 수 있다.
6. **상담 정책**에서 정책을 등록·수정하고 검토한 정책만 활성화한다.

## 기본 모드와 AI 연결

기본값은 AI 비활성이다. API 키 없이도 문의 접수, 관리자 답변, 정책 관리가 동작한다.
비활성 상태에서 가짜 AI 답변이나 평가 결과를 만들지 않는다.

프로젝트 루트의 로컬 `.env`에 다음 설정을 넣는다. 이 파일은 Git에서 제외된다.

~~~dotenv
AI_ENABLED=true
OPENAI_API_KEY=여기에_본인의_API_키
OPENAI_MODEL=gpt-4.1-mini
~~~

키를 채팅, 브라우저 코드, JSP, 저장소에 넣지 않는다.
Docker에서는 `docker compose up -d --build`로 앱을 다시 생성한다.
일반 Tomcat에서는 동일한 환경 변수를 프로세스에 전달하고 재시작한다.
모델은 계정에서 사용 가능한 Responses API 및 Structured Outputs 지원 모델로 변경할 수 있다.
활성화하면 실제 API 사용 비용이 발생한다. 공급자 대시보드에서 사용 한도를 설정한다.

- 활성화와 키 설정 중 하나라도 없으면 수동 모드다.
- 연결 이전에 접수한 문의는 관리자 화면에서 AI 생성을 요청한다.
- 요청에는 문의 제목·본문, 관련 상품 정보, 소유권 확인된 주문 상태와 상품명, 활성 정책을 보낸다.
- 계정의 이름·이메일·비밀번호는 별도로 보내지 않는다. 문의 본문에 직접 쓴 정보는 포함될 수 있어 작성 화면에 안내한다.
- `store=false`로 요청한다. 공급자의 모든 로그·보관 정책을 없앤다는 의미는 아니다.
- 결제·환불·배송 변경 도구는 연결하지 않는다. AI는 초안만 작성한다.

공식 형식: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

## DB 적용과 기존 데이터

신규 설치용 `schema.sql`에 문의 관련 테이블이 포함되어 있다.
기존 설치에서는 앱 시작 시 `SupportBootstrap`이 `db/support.sql`의 `CREATE TABLE IF NOT EXISTS`만 실행한다.
기존 회원, 상품, 주문, 문의를 지우거나 샘플 상품으로 덮어쓰지 않는다.
DB 계정에 CREATE 권한이 없다면 운영자가 먼저 support.sql을 실행해야 한다.
MySQL DDL은 암묵적으로 커밋될 수 있다. 일부 생성 후 실패해도 다음 실행에서 재시도할 수 있다.
향후 컬럼 변경은 별도 버전 마이그레이션으로 추가해야 한다. IF NOT EXISTS는 기존 컬럼을 변경하지 않는다.

정책은 자동 생성하지 않는다. 기존 상품 화면의 “결제 후 2일 이내 출고”, “수령 후 7일 이내 교환” 안내와
실제 운영 조건을 확인한 뒤 정책을 등록한다. 정책 관리가 상품 상세의 정적 안내를 자동 수정하지는 않는다.

## 요청 흐름

`접수 → 입력/소유권 검사 → 문의 커밋 → 작업 예약 → 자료 조회 → AI 호출 → 이력 저장 → 관리자 승인 → 고객 공개`

- 고객 상태: OPEN(답변 대기), ANSWERED(답변 완료).
- AI 상태: DISABLED, PENDING, RUNNING, READY, FAILED, CANCELLED.
- 이력의 SUPERSEDED: 먼저 승인했거나 새 작업이 시작되어 결과를 적용하지 않은 경우.
- 고객 조회에서 초안·내부 사유·작업 토큰을 제거한다. 이력은 관리자만 조회한다.
- 로그인·관리자 필터와 별도로 서비스에서도 역할·소유권을 검사한다.
- 모든 변경은 POST + CSRF. UTF-8 인코딩 필터가 파라미터 읽기보다 먼저 실행된다.
- 답변과 정책의 version을 비교하여 동시 수정의 덮어쓰기를 막는다.
- PAID는 결제 완료만 의미한다. 없는 송장·배송 예정일·수령일은 추측하지 않도록 지시한다.
- 정책은 생성 시점의 스냅샷으로 보관한다. 정책 변경 후 필요하면 초안을 다시 생성한다.
- 상품/주문을 직접 선택하고 작은 정책 집합을 함께 제공한다. 벡터 검색을 구현했다고 주장하지 않는다.

## 실패와 자원 제한

- 외부 연결 5초, 응답 40초 제한. 자동 무한 재시도 없음.
- 작업 스레드 2개, 대기열 20개. 포화되어도 문의는 남고 수동 답변할 수 있다.
- 고객별 10분 동안 접수 5건. 사용자 행 잠금으로 동시 요청에도 검사한다.
- 관리자 재생성은 30초 간격, 문의당 생성 이력 최대 20회.
- 재시작·저장 실패로 RUNNING이 남으면 3분 후 관리자 재시도로 회복한다.
- 메모리 대기열은 영구 큐가 아니다. 재시작 후 PENDING/오래된 RUNNING은 관리자가 재시도한다.
- 정책 최대 12개, 본문 각 6000자. AI에 전달하는 정책도 최대 12개다.
- 잘못된 JSON, 미완료 응답, 거부, 없는 근거 ID는 실패 처리한다.
- 근거가 없으면 담당자 확인 필요로 표시한다.
- 근거 ID 검증만으로 문장 자체의 사실성을 보장하지 않는다. 모든 답변은 담당자가 검토해야 한다.
- SQL 파라미터와 외부 API 원문 오류는 일반 로그에 남기지 않는다.

## 검증과 포트폴리오 설명

`mvn test`는 H2의 MySQL 호환 모드와 임시 Tomcat에서 테스트한다. 운영 데이터나 유료 API는 사용하지 않는다.

- 타인 문의·주문 접근 차단, 관리자 역할, CSRF
- 초안 비공개, 승인 후 공개, HTML 이스케이프
- AI 장애·대기열 포화 시 문의 보존과 수동 처리
- 동시 답변 버전 충돌, 늦은 AI 응답 무시, 만료 작업 재시도
- 정책 스냅샷 보존, 비활성 정책 제외
- 실제 HTTP 요청의 JSON 형식, 근거 ID 검증, 거부·잘못된 응답
- 고객 접수 → 관리자 답변 → 고객 확인 및 정책 관리 JSP 렌더링

H2 검증만으로 MySQL의 모든 동작을 보장하지는 않는다. 실제 배포 환경에서도 같은 흐름을 확인한다.
API 키 연결 후 품질 평가는 별도다. 이력의 모델·프롬프트 버전·시간·토큰 수·원본 초안으로 비교할 수 있다.
`docs/support-evaluation.csv`에 실제 결과를 기록한다. 답변 적합성, 근거 정확성, 추가 확인 판단을 사람이 채점한다.

## 상담 운영 개선 (2026-09-19)

### 검색과 처리 현황

고객과 관리자 모두 제목·본문·상품명·주문번호를 검색할 수 있다. 검색어는 최대 100자이며 %와 _도 문자 그대로 검색한다.
고객 검색의 결과와 총건수는 본인 문의로 제한한다. 관리자 전용 확인 항목을 고객이 URL로 요청하면 403으로 거부한다.
문의 유형·처리 상태·최신/오래된 접수순을 조합하고, 페이지를 바꿔도 검색 조건을 유지한다.
실제 총건수로 마지막 페이지를 계산하며 범위를 넘어선 페이지는 마지막 페이지로 조정한다.

관리자 요약은 검색 조건과 무관한 전체 문의 기준이다.

- 답변 대기: 현재 OPEN인 문의.
- 24시간 이상 대기: 접수 시각으로부터 24시간이 지난 OPEN 문의. 약속한 SLA를 의미하지 않는다.
- AI 확인 필요: OPEN 문의 중 FAILED, 3분 이상 지난 RUNNING, 접수 후 3분 이상 지난 PENDING.
- 오늘 답변 처리: 한국 시간 오늘에 마지막 답변 등록/수정이 이루어진 ANSWERED 문의.

요약 카드를 누르면 해당 필터로 이동한다. DISABLED는 AI 미연결 상태이므로 장애 건수에 포함하지 않는다.

### 안전한 답변 편집

작성한 답변을 sessionStorage에 보관한다. 서버 저장이나 고객 공개가 아니다.
관리자 ID·문의 ID로 구분하며 답변 version도 확인한다.
다시 접속했을 때 복원 버튼을 제공하고, 다른 관리자가 답변을 바꾸었으면 이전 임시 답변을 별도로 보여준다.
버전이 달라진 보관본을 자동으로 덮어쓰지 않는다.
승인 후 돌아온 화면에서는 해당 승인보다 이전 버전의 임시 보관본을 제거한다.
24시간이 지난 보관본은 다음 조회 시 삭제한다. 탭 종료나 브라우저 정책에 따라 더 일찍 사라질 수 있다.
임시 보관이 차단되거나 용량이 부족하면 성공했다고 표시하지 않으며, 보관되지 않은 편집 상태로 이동하려 할 때 경고한다.

### AI 상태 자동 확인

관리자 전용 GET /admin/inquiry/status?id=번호에서 {success,data,message} JSON을 제공한다.
응답은 no-store이며 작업 토큰·계정 정보·생성 이력을 포함하지 않는다.
전체 페이지를 새로고침하지 않고 5초 간격으로 최대 60회 확인한다.
탭이 보이지 않으면 중지하고, 연결 실패가 세 번 이어지면 멈춘다. 상태 확인 버튼으로 다시 시작할 수 있다.
AI를 새로 호출하는 기능이 아니므로 상태 조회 자체는 유료 모델 요청을 만들지 않는다.

초안은 textContent로 표시하고, 편집 중인 답변에 적용하려면 사용자가 버튼을 눌러야 한다.
이미 내용이 있으면 덮어쓰기 확인을 받는다.
다른 화면에서 답변이 승인되면 기존 version으로 게시하지 못하도록 버튼을 막고 최신 답변 확인을 안내한다.
이력과 참고 자료는 새로 불러온 화면에서 확인할 수 있다.

### 추가 회귀 테스트

Java 테스트: mvn test
편집기 테스트: node --test src/test/js/support-editor.test.cjs

Node 테스트는 추가 패키지 없이 실행하며 저장소 차단·버전 충돌·초안 덮어쓰기·연결 실패·숨긴 탭을 검증한다.
HTTP/JSP 테스트는 검색/관리자 통계와 고정 한글 문구, JSON 접근 권한을 확인한다.
각 JSP에 pageEncoding UTF-8을 선언해 include 파일에만 인코딩을 선언했을 때 생기던 한글 깨짐을 수정했다.
